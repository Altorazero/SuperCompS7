# GPU Utilization Implementation

## Обзор

Программа была рефакторена для эффективного использования ресурсов GPU узлов в кластере. Теперь данные распределяются пропорционально вычислительной мощности узлов.

## Конфигурация кластера

### Узлы
- **altogpu1** - GPU узел (CPU + GPU)
- **altogpu2** - GPU узел (CPU + GPU)
- **altocpu1** - CPU узел (только CPU)
- **altocpu2** - CPU узел (только CPU)

### Процессы (8 процессов, 2 на узел)
- Процесс 0, 1 → altogpu1 (GPU)
- Процесс 2, 3 → altogpu2 (GPU)
- Процесс 4, 5 → altocpu1 (CPU)
- Процесс 6, 7 → altocpu2 (CPU)

## Алгоритм взвешенного распределения

### Веса узлов
```cpp
const int GPU_WEIGHT = 3;  // GPU узлы в 3 раза мощнее
const int CPU_WEIGHT = 1;  // Базовая мощность CPU узлов
```

### Расчет распределения

Для кластера с 4 GPU процессами и 4 CPU процессами:
- Общий вес = 4 × 3 + 4 × 1 = 16
- Доля GPU процесса = 3/16 = 18.75%
- Доля CPU процесса = 1/16 = 6.25%

### Пример для 1000 строк данных

| Процесс | Узел      | Тип | Вес | Строк | Процент |
|---------|-----------|-----|-----|-------|---------|
| 0       | altogpu1  | GPU | 3   | ~187  | 18.7%   |
| 1       | altogpu1  | GPU | 3   | ~188  | 18.8%   |
| 2       | altogpu2  | GPU | 3   | ~187  | 18.7%   |
| 3       | altogpu2  | GPU | 3   | ~188  | 18.8%   |
| 4       | altocpu1  | CPU | 1   | ~62   | 6.2%    |
| 5       | altocpu1  | CPU | 1   | ~63   | 6.3%    |
| 6       | altocpu2  | CPU | 1   | ~62   | 6.2%    |

### Итоги
- **GPU узлы**: 750 строк (75%)
- **CPU узлы**: 250 строк (25%)

## Технические детали реализации

### 1. Определение типа узла

```cpp
bool isGPUNode(const char* node_name) {
    string name(node_name);
    return (name.find("gpu") != string::npos || 
            name.find("GPU") != string::npos);
}
```

Функция проверяет имя узла на наличие подстроки "gpu" или "GPU".

### 2. Получение веса узла

```cpp
int getNodeWeight(const char* node_name) {
    return isGPUNode(node_name) ? GPU_WEIGHT : CPU_WEIGHT;
}
```

Возвращает 3 для GPU узлов, 1 для CPU узлов.

### 3. Распределение строк

```cpp
bool shouldProcessLine(int line_number, int rank, int world_size, 
                       const vector<int>& rank_weights, int total_weight) {
    int weight_position = line_number % total_weight;
    int cumulative_weight = 0;
    
    for (int r = 0; r < world_size; r++) {
        cumulative_weight += rank_weights[r];
        if (weight_position < cumulative_weight) {
            return (r == rank);
        }
    }
    
    return false;
}
```

Алгоритм:
1. Вычисляем позицию в цикле весов: `line_number % total_weight`
2. Идем по процессам, накапливая веса
3. Строка назначается процессу, в чей диапазон весов она попадает

### 4. Сбор информации о весах

```cpp
vector<int> all_weights(world_size);
MPI_Allgather(&node_weight, 1, MPI_INT, 
              all_weights.data(), 1, MPI_INT, MPI_COMM_WORLD);
```

Все процессы обмениваются информацией о своих весах через MPI_Allgather.

### 5. Обновленная функция чтения

```cpp
vector<Game> local_games = readCSV(csv_filename, rank, world_size, 
                                   all_weights, total_weight);
```

Функция принимает массив весов и общий вес для корректного распределения.

## Преимущества

### 1. Оптимальное использование ресурсов
- GPU узлы не простаивают
- CPU узлы не перегружены
- Все узлы завершают работу примерно одновременно

### 2. Масштабируемость
- Легко изменить веса для разных конфигураций
- Автоматическое определение типа узла
- Работает с любым числом узлов

### 3. Гибкость
- Можно настроить соотношение весов GPU/CPU
- Поддержка гетерогенных кластеров
- Простое добавление новых типов узлов

## Настройка весов

Для изменения соотношения мощностей отредактируйте константы в `steam_analysis.cpp`:

```cpp
const int GPU_WEIGHT = 3;  // Измените для других соотношений
const int CPU_WEIGHT = 1;
```

### Рекомендуемые значения

| Соотношение | GPU_WEIGHT | CPU_WEIGHT | Использование |
|-------------|------------|------------|---------------|
| Равное      | 1          | 1          | Отладка       |
| 2:1         | 2          | 1          | Консервативное |
| 3:1         | 3          | 1          | **Рекомендуется** |
| 4:1         | 4          | 1          | Агрессивное   |

## Дальнейшие улучшения

### Потенциальные оптимизации

1. **CUDA ускорение** - использование GPU для вычислений
   - Параллельная обработка отзывов
   - GPU-ускоренная сортировка
   - Параллельные математические операции

2. **OpenMP** - гибридная MPI+OpenMP модель
   - Многопоточность внутри узлов
   - Лучшее использование многоядерных CPU

3. **Динамическая балансировка** - адаптация весов во время выполнения
   - Измерение реальной производительности
   - Корректировка распределения на лету

4. **Асинхронный I/O** - неблокирующее чтение файлов
   - Перекрытие I/O и вычислений
   - Уменьшение времени простоя

## Заключение

Реализованное взвешенное распределение позволяет эффективно использовать ресурсы гетерогенного кластера, давая больше работы мощным GPU узлам и меньше работы CPU узлам. Это обеспечивает:

- ✅ Оптимальное время выполнения
- ✅ Равномерную загрузку всех узлов
- ✅ Максимальное использование вычислительных ресурсов
- ✅ Гибкую настройку под конкретную конфигурацию кластера
