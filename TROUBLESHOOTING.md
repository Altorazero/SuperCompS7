# Решение проблемы с CUDA библиотеками

## Проблема

При запуске программы на кластере возникает ошибка:
```
error while loading shared libraries: libcudart.so.12: cannot open shared object file: No such file or directory
```

## Причина

Программа была скомпилирована с CUDA поддержкой (`make cuda`), что означает статическую связь с CUDA библиотеками. Даже если код имеет ветвления для GPU и CPU узлов, бинарный файл требует наличие CUDA библиотек на **всех** узлах во время загрузки, включая головной узел и CPU узлы.

## Решение

### Вариант 1: Использовать CPU версию (Рекомендуется)

Это самое простое и надежное решение:

```bash
# На узле с доступом к исходному коду
cd ~/task
make clean
make                    # Компиляция без CUDA
make install            # Установка в /mnt/share/

# Запуск
sbatch steam_analysis.slurm
```

**Преимущества CPU версии:**
- ✅ Работает на всех узлах без ошибок
- ✅ Не требует CUDA библиотек
- ✅ Использует взвешенное распределение (GPU узлы обрабатывают 75% данных, CPU узлы - 25%)
- ✅ Оптимально использует ресурсы кластера

**Что вы НЕ теряете:**
- Взвешенное распределение нагрузки работает
- GPU узлы получают больше данных для обработки
- Эффективное использование гетерогенного кластера

**Что вы теряете:**
- GPU ускорение вычислений на GPU узлах (~30-50x для некоторых операций)
- Но основное преимущество - взвешенное распределение - сохраняется

### Вариант 2: Установить CUDA библиотеки на все узлы

Если вам действительно нужно GPU ускорение вычислений:

```bash
# На каждом узле (включая головной и CPU узлы):
# 1. Установить CUDA Toolkit или минимум CUDA Runtime
# 2. Добавить в PATH:
export LD_LIBRARY_PATH=/usr/local/cuda/lib64:$LD_LIBRARY_PATH

# Или установить символическую ссылку в системную директорию:
sudo ln -s /usr/local/cuda/lib64/libcudart.so.12 /usr/lib64/
```

После этого CUDA версия будет работать.

### Вариант 3: Использовать разные бинарники (Сложно)

Можно создать два бинарника и запускать нужный на соответствующих узлах:
- `steam_analysis` - CPU версия для CPU узлов
- `steam_analysis_cuda` - CUDA версия для GPU узлов

Но это требует модификации SLURM скрипта и усложняет развертывание.

## Рекомендация

**Используйте Вариант 1** (CPU версия). Это обеспечит:
1. Стабильную работу на всех узлах
2. Оптимизированное распределение нагрузки
3. Отсутствие проблем с зависимостями

Если в будущем понадобится GPU ускорение вычислений, можно:
- Установить CUDA библиотеки на все узлы
- Перекомпилировать с `make cuda` и `make install-cuda`
