# Краткое описание решения

## Что реализовано

Создана полная реализация параллельного анализа данных Steam Games с использованием OpenMPI.

### Файлы

1. **steam_analysis.cpp** - Основная программа на C++ с использованием MPI
2. **steam_analysis.slurm** - Конфигурация для SLURM (4 узла, 2 задачи на узел = 8 процессов)
3. **Makefile** - Для сборки проекта
4. **README.md** - Подробная документация с инструкциями
5. **test_setup.sh** - Скрипт для проверки окружения
6. **games_sample.csv** - Образец данных для тестирования
7. **.gitignore** - Исключение артефактов сборки

## Реализованный алгоритм

### 1. Инициализация MPI
- Инициализация MPI окружения
- Определение количества процессов и ранга
- Работа на 4 узлах (altocpu1, altocpu2, altogpu1, altogpu2)

### 2. Распределенное чтение данных
- Каждый процесс читает файл CSV
- Данные распределяются взвешенно: GPU процессы получают в 3 раза больше строк, чем CPU процессы
- Распределение основано на весах узлов для оптимального использования ресурсов
- Парсинг CSV с учетом кавычек и специальных символов

### 3. Обработка по платформам
Для каждой платформы (Windows, Mac, Linux):
- Фильтрация игр по поддержке платформы
- Группировка может пересекаться (одна игра может поддерживать несколько платформ)

### 4. Группировка по цене
- Игры группируются по ценовым интервалам $5
- Интервалы: $0-5, $5-10, $10-15, и т.д.

### 5. Анализ издателей
Для каждой группы (платформа + ценовой интервал):
- Подсчет количества игр для каждого издателя
- Подсчет общего количества DLC
- Вычисление отношения DLC/игра
- Сортировка издателей по убыванию отношения DLC/игра
- Выбор топ-5 издателей

### 6. Расчет статистики отзывов
Для каждого издателя:
- Вычисление отношения positive/negative для каждой игры
- Расчет математического ожидания (среднего) этих отношений

### 7. Вывод результатов
- Главный процесс (rank 0) записывает результаты в файл
- Структурированный вывод по платформам и ценовым интервалам

## Использование GPU узлов

Программа интеллектуально использует ресурсы GPU узлов:

### Автоматическое определение типа узла
- Определение GPU узлов по имени (altogpu1, altogpu2)
- Определение CPU узлов по имени (altocpu1, altocpu2)

### Взвешенное распределение нагрузки
- **GPU узлы**: Вес = 3 (получают в 3 раза больше данных)
- **CPU узлы**: Вес = 1 (получают базовое количество данных)

### Механизм распределения
1. При запуске каждый процесс определяет тип своего узла
2. Через MPI_Allgather собирается информация о весах всех процессов
3. Данные из CSV распределяются пропорционально весам
4. Строка N назначается процессу на основе накопленных весов

### Результат
- 75% данных обрабатывается на GPU узлах
- 25% данных обрабатывается на CPU узлах
- Все узлы завершают обработку примерно одновременно
- Максимальное использование вычислительных ресурсов кластера

## Параллелизм

- **8 параллельных процессов** (2 на каждый из 4 узлов)
- Взвешенное распределение: GPU процессы обрабатывают 75% данных, CPU процессы - 25%
- Независимая обработка данных минимизирует необходимость синхронизации
- MPI барьеры используются для координации между платформами
- Оптимальное использование гетерогенной архитектуры кластера

## Особенности реализации

### Безопасность
- Обработка пустых полей
- Защита от деления на ноль
- Корректный парсинг CSV с кавычками

### Эффективность
- Минимальная коммуникация между процессами
- Распределенное чтение данных

### Масштабируемость

## Как использовать

### На кластере:
```bash
# Компиляция
make

# Копирование на общую FS
make install

# Копирование данных
cp games.csv /mnt/share/

# Запуск через SLURM
sbatch steam_analysis.slurm

# Просмотр результатов
cat analysis_results.txt
```

### Локально (для тестирования):
```bash
# Компиляция
make

# Запуск с примером данных
mpirun -np 4 ./steam_analysis games_sample.csv

# Просмотр результатов
cat analysis_results.txt
```
